## 4. Individual claims that carry a number or a strong statement

| Claim (location) | Evidence | Limit of the evidence |
|---|---|---|
| GPU faster in every configuration with at least 30,000 returned cells; median 3.0 (fresh) and 4.2 (reused) (Abstract, 4.4) | A files, three sessions | One workstation, one base mesh, warmed implementation. No configuration between 3,000 and 29,977 returned cells. |
| Largest query: 4.02 (fresh) and 6.17 (reused) (4.4) | `A_session1_calls.csv`; first session: 100.318 ms and 24.977 ms (fresh), 81.545 ms and 13.213 ms (reused) | Two separate delivery scopes; not to be mixed. |
| Halos of at most 3,000 cells generally favor the CPU, a few marginal GPU wins (Abstract, 4.4, 5.1) | A files: GPU slower in 29 (fresh) and 30 (reused) of 33 configurations; faster by at most 14% in the others | No crossover is claimed. |
| Process control: high priority and no throttling of execution speed (3.6.3, S7.3) | `benchmarks/process_control.cpp`; `notes` column of the A files | Core placement was not measured. The explanation of the first run is an inference. |
| ± 1 µm changes no cell in seven queries (3.5.2, Table 5) | `E2_buffer_perturbation_1um.csv` | Tests the query parameter, not the arithmetic. |
| Settings study: no failure, same cover and ring, no removed cell, at most 3 and 10 added cells (3.5.2, S6.3) | `G_numerical_settings.csv` | Two settings varied; segment distance tolerance not varied; no independent higher precision reference. |
| Reference setting reproduces the published cells (S6.3) | comparison of `G_numerical_settings/cells/<query>/a1e-05_t0.0001_returned.csv` with `buffer_program/results/<query>_{cpu,cuda}_0_cells.csv` | Seven published queries. |
| Automatic budget sufficient in all measured cases (3.4.5, S5.4) | A files (81 configurations; equal in 33), `F_global_validation.csv` (40 cases; five cover the sphere) | Not proven as an upper bound. |
| Explicit capacity: the latency of the three large queries did not differ, ratios of 1.00 (3.4.5, S5.4, Table 12 row 8) | `D_controlled_variants.csv`, variant `realized_capacity` | One comparison at two capacities; it does not establish that the latency is independent of the capacity or of the size of the hash table. Same engine, retained allocation: no memory saving measured. |
| The allowance of 10 µm is a constant of the implementation and not a setting of the program (3.5.2, S6.1) | literal `1e-5` at four places in `buffer_program/src/coverage.hpp`; the option `--tolerance-m` sets only the classification tolerance | For the settings study the constant was replaced in a generated copy of that file (`revision_tools/build_buffer_settings.sh`). |
| Reservation ring by ring, counting pass (3.4.5, S5.4) | none: designs only | Not implemented, not measured. |
| CPU variant faster in all seven buffer queries (Abstract, 4.7) | `buffer_program/results/benchmark_medians.json` | New process per query; hybrid total includes 74 to 95 ms GPU initialization; earlier GPU halo version. |
